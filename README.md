# 欲罢不能（Can't Stop）

2–4 人的掷骰登山桌游，网页联机版。掷 4 颗骰子两两分组，带着 3 个登山者往 2–12 号登山路上爬；每爬一步都要选再掷还是收手扎营，爆掉就白爬。先登顶 3 条路的人获胜。名字、美术和规则说明文字都是自己的。

线上地址：<https://gulugagame.com/cantstop/>

## 本地运行

```bash
npm install
npm run dev          # 服务端 :3008，网页 :5181
npm test             # 规则引擎、人机、新手教程剧本、服务器（共 51 个用例）
npm run typecheck
```

一个人测试：`node scripts/test-bot.mjs host 2 1` 会让机器人建一个 2 人房并打印房间码，你在网页里用房间码加入凑满后自动开局。机器人随机挑走法，推进后按「再掷爆掉的概率」决定收手还是再掷。`BOT_DELAY_MS` 调思考时间，`BOT_IDLE=1` 只挂着不动，`BOT_GREEDY=1` 更贪（方便看爆掉）。`node scripts/test-bot.mjs host 3 3` 是三个机器人自己打完一整局。

## 规则要点

- 11 条赛道编号 2–12，格数 3/5/7/9/11/13/11/9/7/5/3。
- 掷 4 颗骰子，三种两两分组任选一种；两个和都能走必须都走，只能走一个时任选一个；两个和相同就在同一条路爬 2 格。
- 3 个临时标记（登山者）：每回合最多推进 3 条不同赛道。新上一条路时从自己的营地上方一格开始。
- 推进后选再掷或收手：收手时登山者变成营地；登山者在顶格时收手就占领这条路（撤下别人在这条路上的营地，赛道关闭）。
- 怎么分组都走不了就爆掉，本回合进度全部作废，之前的营地不动。
- 先占领 3 条赛道立即获胜（一次收手可能同时占领两条）。

### 规格书没写清、按默认值实现的地方

| 情况 | 现在的做法 |
|---|---|
| 一种分组的两个和只能走一个 | 两个都列成选项，玩家任选一个（标准规则） |
| 登山者离顶只差 1 格却掷出同一个和两次 | 只走 1 格到顶，第二步作废，这算合法走法 |
| 已经在顶格的登山者又掷到这条路 | 这条路走不了（不算可用的和） |
| 回合计时 | 每一步 45 秒：回合开始没掷骰就超时→跳过这回合；掷了骰没选→自动选第一种走法并收手；推进后没决定→收手 |
| 收手前提示 | 界面显示「再掷爆掉的概率」（枚举 6⁴ 种结果），可以隐藏 |
| 人机 | 房主在等待时点空座位上的「加人机」（咕噜一号 / 二号 / 三号，普通难度），移出用「移出」；一个人加满人机也能开局。人机总是同意再来一局 |
| 托管 | 连续超时 2 次转托管，由人机代打；自己动一下或点「取消托管」就交还。离线的人轮到时先等 3 秒，再由人机代打（不算超时）；用原昵称回来就交还 |
| 新手教程 | 首页和等候房间都有入口。第一次来时是一张邀请卡，不强制；学完或中途退出后只剩「再看一遍」小按钮。在等候房间里看教程不会离开房间，房主一开局就自动回到牌桌 |
| 「提示」 | 只有自己和人机时才有（教程后的练习局、一个人加人机开的房间）；有别的真人就不显示。提示就是人机从你的位置算的那一步，配一句原因；键盘 H |
| 「第一次」小贴士 | 真实对局里第一次爆掉、3 个登山者都派出去、登山者到顶、有人登顶时各弹一次，记在本机；「不再显示小贴士」全站生效 |

|---|---|

| `packages/game/src/board.ts` | 赛道编号和格数、三种分组方式 |
| `packages/game/src/bot.ts` | 人机：本回合价值 = 各登山者多爬的格数 ÷ 赛道长（爬到顶另加分）；再掷还是收手按一步前瞻（爆掉概率 × 丢掉的价值 对比 不爆时平均多拿的价值）；选走法挑走完以后期望价值最大的。模拟对局里对「28 法则」胜率约 62% |
| `apps/server` | Socket.IO 房间、人机座位和托管（`BOT_DELAY_SCALE=0` 让人机立刻行动，测试用）、断线用原昵称回到座位、每一步 45 秒计时（超时自动处理）、语音信令、每局的种子和动作序列写进 `logs/games.jsonl` |
| `apps/web/src/Mountain.tsx` | 山体棋盘：11 根岩柱拼成一座山，登山者（临时标记）、营地小旗（永久标记）、山顶大旗（占领）；攀爬、摔落、插旗动画；鼠标停在走法上时预览登山者会到哪 |
| `apps/web/src/DiceTray.tsx` | 骰子盘：翻滚动画、按分组标色、走法选项、再掷 / 收手、爆掉概率 |
| `apps/web/src/GameBoard.tsx` | 对局界面：舞台、登山队、登山日志、横幅、结算弹窗；「提示」按钮和「第一次」小贴士 |

## 新手教程

咕噜嘎（站名的来历，形象是他给的 24×24 像素画，表情是在原图上改的）在真牌桌上带新玩家走一局「剧本局」，大约 3 分钟；走完接一局和人机的练习，拿不准可以点「提示」。

- **不连服务器**：教程在浏览器里直接跑规则引擎，牌桌就是真正对局的 `GameBoard`（`mode="tutorial"` / `"practice"`），所以界面改了教程跟着变，也不占服务器。
- **剧本** `packages/game/src/tutorial.ts`：一张步骤表，每一步写咕噜嘎说什么、高亮哪个元素（`anchor`）、等玩家做什么。三种步骤：`info`（讲解，点「下一步」）、`do`（等玩家做 `expect` 这一步，做别的会被拦下）、`watch`（对手按 `moves` 自动走，牌桌不压暗）。骰子按 `TUTORIAL_DICE` 出，所以「对手贪心爆掉」这一幕一定发生；剧本骰子用完以后是普通随机数。
- **剧本内容**（21 步，侧栏列 9 课）：山和目标 → 掷骰、两两分组（7 走两步）→ 登山者是临时的 → 再掷、3 个登山者用满 → 爆掉的概率 → 收手扎营 → 看咕噜一号贪心爆掉 → 第二回合：从营地上方接着爬、「只走 4 / 只走 5」为什么只能走一条、2 号路登顶后收手占领 → 先占 3 条路获胜、45 秒限时和托管 → 接练习局。
- **锚点**：界面上要高亮的元素带 `data-tutorial`：`mountain`（岩柱那块棋盘）、`dice`、`roll`、`stop`、`odds`、`hint`、`players`（登山队）、`option:7+7`（选项）、`runner:7`（登山者）、`claimed:2`（被占领的路）。`anchorVisible()` 写了每个锚点在什么局面下看得见，剧本单测用它检查。
- **剧本单测** `tutorial.test.ts`：从头走到尾每一步合法、高亮的东西看得见、剧本骰子正好用完、关键几幕一定发生（含第二回合的「只走一条」选项和登顶占领）、走完接练习局 120 局都能打完。改规则或改剧本后跑 `npm test`。
- **教练层**（各游戏共用，复制时整个文件夹一起拷）`apps/web/src/tutorial/`：`Coach.tsx`（对话框、压暗和高亮、箭头、小贴士条）、`gulu.ts`（咕噜嘎像素图和表情）、`useTutorial.ts`（剧本推进、对手自动走、练习局人机）、`tips.ts`（「第一次」小贴士）、`storage.ts`（本机记录：`gm-tutorial-cantstop`、`gm-tips-cantstop`、全站的 `gm-tips-off`）、`Invite.tsx`（首页 / 等候房间的入口）、`tutorial.css`。
- **本游戏自己的部分**：`apps/web/src/TutorialMode.tsx`（把剧本、引擎、人机接到教练层上）、`apps/web/src/tutorialGame.ts`（「提示」的说法、小贴士的内容和触发条件）。
- **走查**：`~/projects/qa-reports/tools/tut-cantstop.mjs`（先 `npm run dev` 和 `npm run build -w packages/game`，剧本从 dist 读）：`flow` 逐步量化（高亮在不在、被不被对话框挡、字号、截断、滚动）走完教程和一整局练习，`skip` 看 `?tutorial` 直接打开和中途跳过，`waiting` 在等候房间里看教程、凑满开局自动回牌桌，`room` 看人机房间里的「提示」和第一次爆掉的小贴士；四种屏幕 × 白天/夜间截图。地址带 `?tutorial` 直接打开教程。

## 美术流水线（`art/`）

PixelLab API，密钥只在 `~/.config/pixellab/api_key`，不进仓库。每次调用记进 `art/ledger.jsonl`，`BUDGET_USD` 设上限。生成的原图和中间文件在被 gitignore 的 `art/out/`。

- `pixellab.py`：API 客户端（同步出图、后台任务轮询、角色和动画），调用即记账。
- `r1.py`：第一轮候选。小图用 `/generate-image-v2`（≤42px 一次出 64 个候选），场景大图用 `/create-image-pixen`（512×288）。
- `sheet.py`：把一批候选拼成对照图。
- `selection.json` + `export.py`：选定的图导出到 `apps/web/public/art/`。登山者、头像、营地小旗、山顶大旗只画红色一套，其他座位色把红色像素换色；骰面在选定的空白骰子上按点数画点。

## 画面：白天版和夜间版

只有像素风一种画面（原始版本已删掉），配色分夜间（深色，默认）和白天（白底）两种。顶栏「切换白天版 / 切换夜间版」随时切换，只影响自己看到的画面，记在浏览器的 `gm-pixel-theme` 里；gulugagame.com 上的大厅和各个游戏同源，共用这一个选择。

- 夜间配色就是 `app-pixel.css`（首页和等候房间）和 `cantstop.css`（牌桌）本身。白天版不单独写：`apps/web/day-theme.ts`（Vite 插件）在构建时把这些样式里和颜色有关的声明照抄一份，选择器前加 `:root[data-theme="day"]`，按 `apps/web/day-palette.ts` 的调色表换成白天的颜色。改夜间样式时白天版自动跟着变，只有新出现的深色需要在调色表里补一行。
- 机械换色不合适的地方在 `apps/web/src/theme-day.css` 里手写。
- `index.html` 里一小段脚本在样式生效前就给 `<html>` 加上 `data-theme="day"`，打开页面不会先闪一下深色；切换逻辑和按钮在 `src/theme.tsx`。

## 背景音乐

进了房间（等候房间、对局、观战）和新手教程里循环放 `apps/web/public/bgm/cantstop.mp3`，首页和房间列表不放。曲子是他用 Suno 做的，原文件在桌面 `bgm v1/欲罢不能.mp3`（2026-10-11 接入）。播放器是 `apps/web/src/bgm.tsx`（大厅和各游戏是同一份文件，改了要同步到所有仓库）：一个页面只有一个播放器，从等候房间进牌桌不会从头放；循环处交叉淡化；切到别的标签页时暂停。顶栏的 ♪ 按钮能开关、调音量，设置全站共用（localStorage `gm-music`、`gm-music-volume`，默认开、音量 60）。浏览器要求先点过页面才能出声，从首页点进房间正好满足。

换曲子：把新文件放进 `apps/web/public/bgm/`，用 `~/miniconda3/envs/quant/bin/python -I ~/projects/qa-reports/tools/bgm-analyze.py <文件>` 量出 gain / start / end，改 `App.tsx` 里的 `BGM`。本地检查：`URL=http://localhost:<网页端口>/ node ~/projects/qa-reports/tools/bgm-check.mjs`（进房间、开局、离开、开关、顶栏是否被挤成两行）。

### 音效

动作音效在 `apps/web/src/game-sfx.ts`（`useGameSfx`，GameBoard 和新手教程共用），按每一步的引擎事件出声，全部用 `gm-sound.tsx` 即时合成：掷骰 → 骰子声；爆掉 → 落石（招牌）+ 下滑音；选组合前进 → 脚步（走几步响几下），登山者爬到顶 → 上扬一声；收手扎营 → 钉帐篷两下；登顶 → 山顶号角（招牌）+ 得分，别人营地被撤下 → 一击；超时、轮到你、交出回合、终局赢/输、再来一局都有提示音。自己的动作响，别人的减半；最后 5 秒倒计时每秒一声。房间里有人进出、开局、收到聊天、操作被拒绝也有提示音（`App.tsx`）。音量在 ♪ 面板的「音效」滑杆。
